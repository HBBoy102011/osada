# Архитектура «Осады»

## Общая схема

```
┌──────────────────────────── Браузер ────────────────────────────┐
│  main.ts                                                        │
│   ├─ меню, лобби, реконнект                                     │
│   ├─ OfflineSession: World + Bot (локально)                     │
│   └─ OnlineSession: команды в WebSocket                         │
│  Game + Scene (Three.js) + Hud (DOM)                            │
└───────────────────────────────┬─────────────────────────────────┘
                                │ /ws, JSON-сообщения
┌───────────────────────────────▼─────────────────────────────────┐
│  Node.js                                                        │
│   app.ts: HTTP-статика, /api/health, /api/balance, WebSocket    │
│   rooms.ts: RoomManager → Room                                  │
│   shared: World (20 Гц), Bot, map, navgrid, protocol            │
└─────────────────────────────────────────────────────────────────┘
```

Клиент и сервер импортируют **один и тот же** `src/shared/world.ts`.
Оффлайн-режим — это не отдельная упрощённая версия: он крутит тот же `World`
в браузере и добавляет `Bot` для второй стороны. Онлайн-режим отправляет
команды на сервер, где тот же `World` исполняет их и рассылает снапшоты.

## Симуляция

- **Тик.** Сервер вызывает `World.tick(dt)` каждые 50 мс (20 Гц), `dt`
  ограничен 0,2 с, чтобы длинная пауза не телепортировала юнитов.
- **Детерминизм.** Внутри `World` нет `Math.random`, `Date.now` и обращений
  к DOM. Случайность карты и боёв идёт через `Rng` с seed. Бот тоже использует
  собственный `Rng` (seed карты + сторона), поэтому матч бот против бота
  воспроизводится в тестах тик в тик.
- **Состояние.** `World.entities` — юниты и здания, `World.nodes` — ресурсы,
  `World.players` — экономика, технологии, навыки героя, статистика.
  Проходимость — статическая сетка карты плюс динамические здания.
- **Команды.** `World.applyCommand(team, cmd)` проверяет владельца, стоимость,
  лимиты, радиусы, фазу матча и состояние очередей. Любая ошибка возвращает
  `{ ok: false, error }`; сервер отправляет её клиенту.
- **Победа.** Проверяется после каждого тика: отсутствие главного зала,
  сдача, истечение 20 минут. Ничья возможна при уничтожении обеих баз.

## Карта и путь

`src/shared/map.ts` генерирует карту из seed: базы, 14 месторождений,
деревья, трофеи и статические препятствия. `createNavGrid` строит сетку
проходимости с шагом 1,5.

`src/shared/pathfinding.ts` — A* по 8 направлениям:

- без срезания углов (диагональ запрещена, если обе соседние клетки заняты);
- бинарная куча для открытого списка;
- сглаживание пути по прямой видимости;
- `nearestFree` для цели внутри препятствия;
- динамические здания блокируют и разблокируют клетки при постройке/смерти.

## Протокол

Один WebSocket на комнату, JSON-сообщения (`src/shared/protocol.ts`).

Клиент → сервер:

- `join` — создать комнату (`room` пустой) или войти по коду/токену;
- `cmd` — игровая команда (`move`, `attack`, `build`, `train`, `research`,
  `tier`, `heroSkill`, `heroAbility`, `surrender`, …);
- `chat`, `ping`, `leave`.

Сервер → клиент:

- `welcome`, `joined` (код, команда, роль, токен), `lobby`, `countdown`;
- `start` (баланс, карта, состав игроков, признак реконнекта);
- `snapshot` (8 Гц), `chat`, `pong`, `opponentStatus`, `end`;
- `error`, `notice`.

Максимальный размер сообщения — 64 КБ; сервер пингует сокеты каждые 30 секунд
и закрывает мёртвые соединения.

## Комнаты и реконнект

- Код комнаты — 4 символа из алфавита без похожих `0/O`, `1/I`.
- Первый игрок выбирает роль (или получает случайную), второй — противоположную.
- Когда подключены оба, идёт отсчёт 3 секунды и создаётся `World`.
- Каждый слот хранит токен (`randomUUID`) и таймер отключения.
- При обрыве соперник получает `opponentStatus` и уведомление; слот ждёт
  60 секунд. Возврат по токену отменяет таймер и присылает `start`
  с `reconnect: true`. Иначе `world.forfeit(team)`.
- После конца матча комната живёт ещё 10 минут, чтобы оба игрока увидели
  экран результата, затем удаляется.

## Туман войны

`World.snapshot(team, withFog)` собирает снапшот **для конкретной команды**:

- свои юниты и здания видны всегда;
- чужие — только в радиусе обзора своих юнитов/зданий;
- нейтральные трофеи — по тому же правилу;
- узлы ресурсов видны всегда, но их количество не скрывается;
- экономика и технологии противника не передаются (`enemy.gold = 0`).

Маска тумана кодируется base64 (`Uint8Array` по клеткам) и используется
клиентом для затемнения сцены. Противник не может подсмотреть скрытые войска
через DevTools: их просто нет в полученном JSON.

## Клиент

- `Game` — ввод, выделение, приказы, размещение зданий, миникарта, чат.
- `Scene` — Three.js: карта, здания, юниты, снаряды, эффекты, туман,
  подсветка выделения. Позиции снапшотов сглаживаются лерпом.
- `Hud` — DOM: ресурсы, таймер, выделение, командная карточка, герой,
  технологии, журнал, экран результата.
- Онлайн-клиент хранит токен в `sessionStorage`; при разрыве переподключается
  с задержкой 2,2 с, пока не истекут 55 секунд.

## Производительность и масштабирование

MVP рассчитан на один Node-процесс и небольшое число комнат. Симуляция
дешёвая: один тик — обход десятков сущностей; A* вызывается только при
изменении приказа. Снапшоты — компактный JSON.

Ограничения: комнаты в памяти, нет Redis/БД, нет горизонтального шаринга.
Для продакшена следующим шагом были бы вынесение комнат в отдельные воркеры,
NATS/Redis для сообщений и матчмейкинг.

## Тестирование

Vitest запускает четыре набора:

- `world.test.ts` — 23 сценария симуляции;
- `pathfinding.test.ts` — геометрия и A*;
- `bot.test.ts` — 5 минут симуляции бот против бота;
- `server.test.ts` — реальный HTTP + WebSocket на эфемерном порту,
  два клиента, чат, команды, сдача, реконнект.

CI (`.github/workflows/ci.yml`) выполняет `npm ci`, typecheck, тесты, сборку
и smoke-тест `/api/health` на собранном сервере.
